Automaton User Manual

Pipeline Automation for Blender

01 Introduction

Automaton is a powerful pipeline automation add-on for Blender that allows you to execute Python scripts automatically based on specific application events (like saving, rendering, or changing frames).

Heavily integrated with Blender's native Project API, Automaton ensures your entire team runs the exact same validation, output generation, and pipeline standards seamlessly, directly from your shared project repository.

02 Core Concepts

Automaton operates on three basic concepts:

Blender Projects

Automaton hooks directly into your active Blender Project. Configurations and scripts are evaluated relative to your active Project Root.

Targets

The specific Python script (or directory of multiple scripts) you want to execute when an event occurs.

Rules

The overarching configuration that dictates when a target fires (Triggers) and where it is allowed to fire (Filters).

03 Getting Started

3.1 Installation

  1. In Blender, go to Edit > Preferences > Add-ons.
  2. Click Install... and select the downloaded Automaton zip file.
  3. Enable the checkbox next to Pipeline: Automaton.

3.2 Project Setup

Because Automaton utilizes Blender's native Project system, there is no complex setup. Just ensure you are working within a defined Blender Project.

  • Open Blender's Project preferences. Automaton will automatically detect your active Project.
  • Define your Scripts Folder. This is a relative path inside your project where your automation .py files are stored (defaults to scripts).
Shared Pipeline Configuration

Automaton automatically saves your rules to an automaton.json file located inside your project's hidden .blender_project directory. Commit this file to your repository so your entire team shares the same rules instantly!

04 Creating Rules

A rule connects a script Target to a specific Blender event Trigger.

  • Click the + (Add) button under the Rules List in the Project preferences.
  • Select your Target (a specific .py file or a whole folder to run recursively in alphabetical order).
  • Select your Trigger (e.g., "Before Save", "After Render").

Blender Version Targeting

You can restrict a rule to only run on specific Blender versions, keeping legacy scripts from breaking in newer releases.

  • Use + for "this version or newer" (e.g., 5.2+).
  • Use - for "this version or older" (e.g., 4.2-).
  • Comma-separate multiple targets (e.g., 4.0, 5.2+). Leave empty to run globally.

Execution Controls

Prevent heavy scripts from running too often:

  • Once Per Session: The rule will only execute the very first time the trigger occurs, and won't run again until Blender is restarted.
  • Cooldown (Hours): Sets a minimum time limit between executions. (e.g., 2.0 runs once every 2 hours max).

05 Filtering and Scoping (Where scripts run)

You likely don't want every script running on every .blend file. Automaton provides powerful path and filename scoping using simple wildcards to strictly control execution.

Directory Scope (Include / Exclude)

Evaluated relative to the Project Root.

  • assets Matches the 'assets' folder exactly at the project root.
  • */props/* Matches any folder named 'props' anywhere in the project.
  • shot_0? Matches 'shot_01', 'shot_02', etc.

File Filters (Include / Exclude)

Evaluates the blend file's name.

  • rig Matches any file containing 'rig' (e.g., hero_rig.blend).
  • *_v01.blend Matches files specifically ending with '_v01.blend'.
  • Use commas to separate multiple filters (e.g., rig, anim).

Dry Run Target List

Not sure if your wildcards are targeting the right files? In the rule details, click Dry Run Target List. Automaton will recursively scan your project directory and print a list of every single .blend file that matches your conditions straight into the Blender System Console.

06 The N-Panel Interface (Manual Control)

Automaton provides a user interface in the 3D Viewport and the Video Sequencer (VSE). Open the side panel (shortcut N) and look for the Automaton tab.

6.1 Running Scripts Manually

  • The panel lists all valid scripts for the currently open file (based on your Scopes and Filters).
  • Click the Play button next to a script or directory to execute it immediately, bypassing triggers or cooldowns.

6.2 Local Overrides (Toggling Rules)

  • Underneath each script, you will see a checklist of its active automated rules.
  • Unchecking the box next to a rule creates a Local Override.
  • This completely disables that automation rule only for the current scene. This is saved within the .blend file, allowing artists to bypass specific automations when necessary without breaking the shared pipeline config for everyone else.
